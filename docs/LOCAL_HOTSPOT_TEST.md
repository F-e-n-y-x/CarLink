# Standalone 5 GHz local hotspot

This transport is optional; existing Wi-Fi Direct and car-hotspot choices keep their settings. The app requests and releases its own Android LocalOnlyHotspot reservation. The car does not need an internet subscription. The phone still needs mobile data or downloaded maps for navigation data. No ADB, root, Shizuku or separate helper is needed at runtime.

On the tested DiLink 5.1/Android 13 firmware, Nearby devices permission allows the configured 5 GHz reservation through a capability-checked framework SystemApi. This is firmware-dependent, not a guarantee for every Android 13 device. API 36+ uses the configured-hotspot entry point. The firmware can override the requested channel; a fixed request is not proof that the AP stayed on it.

Select **Native Android Auto → Network transport → Local hotspot**, apply, and allow normal Nearby devices/Location permission prompts. The new **Open car Wi-Fi settings** link lets DiLink 5.1 owners try turning off the car's Wi-Fi switch before connecting. Keep Bluetooth and the Android phone's Wi-Fi on. To return to Wi-Fi Direct, enable the car's Wi-Fi again. Close the other projection app before starting.

The provider publishes only a new AP-capable interface, excludes all observed upstream interfaces, rejects ambiguous/missing addresses, and owns only its own reservation. Cancellation closes late reservations, stale callbacks cannot publish credentials, and leaving this transport does not remove another application's P2P group. Unsupported configured-5-GHz startup fails explicitly instead of silently selecting 2.4 GHz.

On 27 September 2026, the installed DiAuto build connected a OnePlus 15 through native Bluetooth setup and its own 5 GHz hotspot (observed 5745 MHz). During a three-minute parked test with the car Wi-Fi client off, the user reported smooth playback and a maintained connection. Across 170 seconds of complete decoder windows there were zero input drops, 28 render catch-up skips, no reported whole-link gaps over 1.2 seconds, and no unexpected disconnects. Output varied with content; this was not a constant-frame-rate benchmark. The normal Stop Connection action released the hotspot.

Android Auto logging does not measure audio underruns/packet sequence loss in the same way as DiPlay, so those DiPlay-specific metrics must not be attributed to this test. A separate fresh-process start with the client already off created the hotspot and rendered its first picture in 12.8 seconds. The next 150 seconds had zero decoder input drops, 31 render catch-up skips, and no reported whole-link gaps or unexpected disconnects. After returning to Wi-Fi-client-off use, the owner again confirmed Android Auto was smooth and connected, and accepted both apps for wider testing. Spotify was paused in the fresh-start snapshot, so that snapshot alone does not validate sustained music playback. These are observations on one phone and firmware, not a universal performance or compatibility guarantee. A drive/reboot test and other-device coverage remain outstanding.
