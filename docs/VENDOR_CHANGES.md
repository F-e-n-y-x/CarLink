# Changes to the vendored engines

CarLink imported both engines with `git subtree`, keeping their history:

| Path | Upstream | Engine |
|---|---|---|
| `vendor/diplay` | https://github.com/shihabal3amri/DiPlay (fork: F-e-n-y-x/DiPlay). Imported at 9e244d9, updated to **upstream main 615b32ce0** (2026-10-28, DiPlay 0.2.22: security bounds on AirPlay/iAP/NCM/bplist input, data sockets accept only the control peer, USB permission receivers guarded on Android 12 and older, queued session log, merged touch moves, Korean and Turkish; earlier updates 9d8963303 on 2026-10-24, 143f4674b on 2026-10-21, 6d3b8a8ce / 0.2.21 on 2026-10-19, bc2bdb3e7 / 0.2.19+ on 2026-10-15, 6ebb5821 / 0.2.16 on 2026-10-10 and 292b2dd, CarLink commit 5eeed506) | CarPlay, main process |
| `vendor/diauto` | https://github.com/shihabal3amri/DiAuto (fork: F-e-n-y-x/DiAuto). Imported at a2119f4, updated to **upstream main d53dad71e** (2026-10-19, DiAuto 0.3.12+: the 0.3.12 release plus the dashboard-map follow-ups) | Android Auto, `:aa` process |

**Neither engine is updated with `git subtree pull`.** For DiAuto the subtree pull found no
merge base either, so it is updated the same way as DiPlay below (its recorded upstream commit is
d53dad71e now; leave out `.github`, `.gitignore` and `.editorconfig`, and use
`--directory=vendor/diauto`: the subtree holds DiAuto's repository root). For DiPlay, a history rewrite (filter-repo) changed
the stored copies of the old DiPlay commits, so the subtree lost its merge base and a subtree pull
no longer finds what CarLink last imported. Apply the upstream diff since the upstream commit
recorded in the table above instead (`<recorded>` is that commit, 615b32ce0 now; leave out the
repository-root dotfiles, which the subtree does not carry):

```sh
git fetch https://github.com/shihabal3amri/DiPlay main
git diff --binary <recorded> FETCH_HEAD -- . ':!.github' ':!.gitignore' > p.patch
git apply -3 --directory=vendor/diplay p.patch
```

`git apply -3` merges each file three-way against the recorded upstream version and leaves
conflict markers where a CarLink edit meets an upstream change. Resolve them with this list, then
record the new upstream commit in the table above and in the audit command below. The patch does
not reach files outside `vendor/diplay`: copy new entries of upstream's `gradle/libs.versions.toml`
into CarLink's root catalog (0.2.19 added `zxing-core` and `androidx-work-runtime`; 0.2.21, 143f4674b, 9d8963303 and 615b32ce0 added none).

Watch on the next DiAuto update: if it brings open-headunit `1a6bf477` (releasing the video decoder
in `AapProjectionActivity.onStop`), bring open-headunit PR #1141's delayed release with it, or the
projection goes black after the reverse camera (open-headunit #1137). DiAuto 0.3.12 doesn't have it.

Watch on the next DiPlay update (open upstream PRs on 2026-11-03, not in 615b32ce0): #1124 refuses
SETUP/RECORD/TEARDOWN/`/command` before pair-verify and #1130 caps idle AirPlay control
connections (both close an unauthenticated hotspot attack surface); #1178 keeps the Wi-Fi tunnel on
an RFCOMM EOF after setup; #1071 advertises every hotspot address. 615b32ce0's data-socket peer
check (#1123) logs "rejected sender outside the control session" when it refuses a connection: look
for that line first if a wireless or USB session has control but no picture. CarLink already carries ports of
the open PRs #1206, #1212, #1218, #1251, #1261–#1265, #1270, #1276, #1280, #1283 and #1284 (rows below): when an update brings one, take upstream's version
and drop its row (for #1212 keep CarLink's writer-thread `close` wait in `NcmUsbBridge`).

Every edit inside `vendor/` is listed below, so a conflicting pull is easy to resolve. Code edits
carry a `// CarLink` comment (new files say so in their header); the build-file changes, the
renamed native library, the `com.carlink.app` package allowlists and DiAuto's `homeActivity`
intent sites are the unmarked exceptions. Keep this list current. To audit it against the code:

```sh
git diff --stat 615b32ce0: HEAD:vendor/diplay    # DiPlay edits since upstream 615b32ce0 (0.2.22)
git diff --stat d53dad71e: HEAD:vendor/diauto    # DiAuto edits since upstream d53dad71e (0.3.12+)
grep -rn "CarLink" vendor/
```

After a pull, run `python3 scripts/resource_collisions.py` and the build and test checks in [BUILDING.md](BUILDING.md#build-and-test).

## Engine wording changed only through CarLink's resources

App resources override library resources of the same name, so these need no engine edit:
`app/src/main/res/values/carlink_engine_overrides.xml` rewords the engine strings the driver can
see during a session (CarPlay picture messages, dashboard-map placeholder, wheel-key accessibility
service, Android Auto service and boot-loop notifications), and copies of `ic_stat_carlink`
replace DiAuto's `ic_stat_aa` (`drawable-anydpi-v24`) and DiPlay's `ic_diplay_notification`.
`carlink_engine_theme.xml` recolors DiAuto's `da_*` colors (its dialog theme, used by the
projection's exit menu) to Graphite and Ion, `drawable/bg.xml` replaces DiAuto's blue window
background, and `layout/dialog_exit_item.xml` gives the exit menu Inter and car-sized rows (same ids;
re-check after a DiAuto pull). The CarPlay menu title, the side-panel button and the Android Auto
exit-menu labels are reworded there too. Each name is in `scripts/resource_collisions_allowlist.txt`. Strings only DiPlay's or DiAuto's own
screens use are left alone. CarLink also sets DiAuto's `vehicle-display-name` (the car name the
phone shows) to "CarLink" when the driver never chose one. Likewise it sets DiPlay's CarPlay manufacturer and model (what
the iPhone shows for the car) to "CarLink" while they are still DiPlay's default "DiPlay".

## Behaviour changed only through CarLink's manifests (`carlink-core/src/main/AndroidManifest.xml`, `app/src/main/AndroidManifest.xml`)

The engine overrides below live in the backend library's manifest, so every host of `:carlink-core`
gets them; the app manifest adds only `HomeActivity` and CarLink's UI entries.

- CarLink's `HomeActivity` is the only launcher. `UsbRouterActivity` is the only USB-attach handler.
  `SystemEventReceiver` replaces DiPlay's `BootReceiver` and DiAuto's boot, Bluetooth and Wi-Fi
  auto-start receivers.
- DiAuto's `MainActivity` no longer handles `geo:`/navigation links: opening it starts `AapService`,
  which must not happen while CarPlay runs.
- DiAuto's `com.andrerinas.openheadunit.permission.NAVIGATION_UPDATE` is removed and
  `<applicationId>.permission.NAVIGATION_UPDATE` declared instead (#30: Android refused CarLink
  when Open Headunit, signed by someone else, was installed).
- `ACCESS_LOCAL_NETWORK` is declared: CarLink targets SDK 37, where Local Network Protection
  otherwise drops local IPv4 and wireless CarPlay never gets its AirPlay TCP (DiPlay #425,
  DIPLAY.md F4). DiPlay's own `shared` manifest declares it too since upstream 292b2dd (PR #465);
  CarLink keeps its declaration so the permission does not depend on the engine's manifest.
- Every DiAuto component runs in `:aa`, so `System.exit` on disconnect, `AppComponent`
  singletons, car mode and Conscrypt stay out of the CarPlay process.
- DiAuto's `AutomationActivity` (actions and `headunit://connect|disconnect|nightmode|exit`) and
  `AapProjectionActivity` are not exported (DA§10.9); `AutomationActivity` also loses its intent
  filters. Any other app could otherwise start, stop or switch the Android Auto engine. CarLink
  reaches both through explicit intents.
- DiAuto's `CarKeyReceiver`, `RemoteControlReceiver` and `MediaButtonReceiver` ship disabled.
  `connection/DeviceEnvironment` enables them only while Android Auto is engaged: `CarKeyReceiver` aborts
  every ordered key broadcast and would otherwise take the steering-wheel keys from CarPlay.
